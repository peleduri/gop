# Adopters

This file lists organizations and projects that use gop. It helps prospective users see where gop runs, and the CNCF asks projects to keep one. The format follows the [CNCF project template](https://github.com/cncf/project-template/blob/main/ADOPTERS.md); for what counts as an adopter, see the [CNCF TOC FAQ](https://github.com/cncf/toc/blob/main/FAQ.md#what-is-the-definition-of-an-adopter).

No adopters are listed yet. If you use gop, please add yourself: it is the most useful thing you can do for the project after reporting how a run went.

## Adopters list

| Organization | Type | Adoption level | Description |
| ------------ | ---- | -------------- | ----------- |

**Type:** End-User Organization (uses gop internally), Service Provider (offers gop as part of a service), Project (an open source project that integrates with gop), Consultancy (helps others use gop).

**Adoption level:** Production, Dev/Test, Trialing, Evaluating.

## Adding your organization

Open a pull request that adds one row to the table above, signed off as described in [CONTRIBUTING.md](CONTRIBUTING.md#sign-off-dco). Describe how you use gop (for example "weekly scheduled run in GitHub Actions across our enterprise" or "MCP server for our security team's agent") without naming internal orgs, repositories or findings: this is a public repository.

If your organization prefers not to be named, you may list the industry instead (for example "Financial services company"). Only list an organization you are allowed to speak for.
