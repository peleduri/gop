Which AI agents and people can make code run where in your GitHub Enterprise.

gop maps every org, repo, workflow and Action into one evidence graph, follows reach across org boundaries and nested Actions, and ranks the few changes that remove the most of it. Every hop says how it is known.

Get started

From zero to your first answer in a minute

One static binary. Try it on the demo graph first, then point it at your enterprise with a read-only token.

  1. Install

    Builds from source with your Go toolchain.

    $ go install github.com/peleduri/gop/cmd/gop@latest

  2. Try it, no token

    A synthetic enterprise, no network.

    $ gop report --demo --out report.html

  3. Run it on yours

    Read-only token, results stay on disk.

    $ gop collect --enterprise acme \
    --out graph.json
$ gop report --graph graph.json \
    --out report.html

Built to be trusted

Read-only, local, never phones home

gop is meant to run with a token that can see your whole enterprise. It is built so that token can never be used to change anything.

  • Read-only

    The API client refuses every non-GET REST request and every GraphQL mutation before it is sent. Every MCP tool is annotated read-only.

  • Local

    The graph and the report are written to your disk with file mode 0600. The report is one HTML file with a strict content security policy.

  • Never phones home

    No telemetry. gop sends nothing anywhere except read requests to the GitHub API. This page has no cookies, analytics or external assets either.

Questions

Frequently asked

How do I find out who can make code run across all my GitHub orgs?

Run gop collect --enterprise acme --out graph.json with a read-only token, then gop report --graph graph.json --out report.html, or ask your AI assistant through the gop MCP server. gop follows push access, workflows, nested Actions, secrets, OIDC trusts and self-hosted runners across every org, and shows each path hop by hop.

Which AI coding agents in GitHub Actions can outsiders start?

gop finds workflows that run a coding agent, who can trigger each one (including people without push access, for example through an issue comment), what untrusted text reaches its prompt, and what its token, secrets and tools let it do. See the AI agents in CI guide.

Is it safe to run with a token that can see the whole enterprise?

gop is read-only: its API client refuses every non-GET request and every GraphQL mutation before sending it, and every MCP tool is annotated read-only. It has no telemetry and sends nothing anywhere except read requests to the GitHub API. The graph and reports are written with file mode 0600. See the threat model.

How do I add gop to Claude Code, Claude Desktop, Cursor, Codex or VS Code?

Claude Code: /plugin marketplace add peleduri/gop then /plugin install gop@gop. Claude Desktop: open the .mcpb extension attached to each release. Cursor: the install link above. Codex: codex mcp add gop -- gop serve --graph /path/to/graph.json. VS Code: gop mcp-config --client vscode --graph graph.json. Other clients find io.github.peleduri/gop in the official MCP Registry. What is the difference between confirmed and possible reach?

A path is confirmed when every hop was observed (live, inferred by a documented rule, recent audit or a file you supplied). A path with any hop the token could not see is possible: unknown, not absent. Possible reach is never added to headline numbers, scores or fix suggestions, and gop never reports what it could not see as off.

Does gop work with GitHub Enterprise Server?

Yes. Pass --github-url https://HOST to gop collect; APIs your server version lacks are reported as not visible. See GitHub Enterprise Server.

How is gop different from OpenSSF Scorecard or a workflow linter?

Scorecard checks how one repo is configured and a workflow linter checks one workflow file. gop joins them across the enterprise: it shows that members of another org can change what a workflow runs, through which hops, and which change removes most of that. Use them together; see how gop compares.
